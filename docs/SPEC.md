# TG Native Kit — Figma-плагин для дизайна нативных Telegram Mini Apps

> Документ-задача для разработки в Claude Code. Описывает проблему, цель, скоуп MVP, требования и технические опоры.

---

## 1. Для кого и зачем

### Нативный подход
Есть два способа делать Telegram Mini App:
1. **Кастомный** — своя палитра и бренд, приложение выглядит как отдельный продукт. **Этот плагин не для него.**
2. **Нативный** — приложение берёт цвета из темы Telegram, которую выбрал пользователь, и ощущается как часть самого Telegram. **Плагин — для этого подхода.**

При нативном подходе контент красится через **theme params**. Клиент Telegram передаёт их в `window.Telegram.WebApp.themeParams` и launch-параметре `tgWebAppThemeParams`, а SDK прокидывает в CSS-переменные вида `--tg-theme-bg-color`. Вокруг контента — **системная обвязка** Telegram (шапка, нижние кнопки, попапы), которая тоже рисуется в теме пользователя.

### Проблема
Дизайнер нативного Mini App проектирует интерфейс, **цвета которого заранее неизвестны**: у каждого пользователя своя платформа (iOS / Android / Desktop), светлая или тёмная тема, а иногда кастомная тема с почти любыми цветами.

Конкретные боли:
1. **Макет рисуют в одной теме**, обычно в светлой iOS. Как он выглядит в тёмной Android или в кастомной фиолетовой, узнают в проде.
2. **Нет связи «слой → theme param».** В Фигме цвет — просто hex. Разработчик угадывает, где `hint_color`, а где `subtitle_text_color`. Ошибки здесь незаметны в одной теме и вылезают в другой.
3. **Ручная проверка дорогая.** Чтобы посмотреть экран в 5 темах, его надо 5 раз продублировать и перекрасить руками. Этого никто не делает.
4. **Типичные баги находят поздно:** захардкоженный белый фон в тёмной теме, текст на `button_color`, который в чужой теме нечитаем, `hint_color` на `secondary_bg_color` с плохим контрастом, иконки, которые не перекрашиваются.
5. **Нет нормальных системных компонентов.** Шапку Mini App, MainButton/SecondaryButton и попапы рисуют со скриншотов, в одной теме, без состояний. Community-киты статичны и не связаны с темами.

### Почему решения нет
Общие плагины для тем и переменных не знают модель цветов Telegram. Китов с мокапами Telegram несколько, но они не перекрашиваются темой пользователя и не покрывают состояния системных кнопок.

---

## 2. Цель

Дать дизайнеру нативного Mini App набор, в котором:
1. **цвета макета привязаны к theme params Telegram**, а не к hex;
2. **любой экран за один клик виден во всех основных темах** Telegram;
3. **системные компоненты Telegram** (шапка в оконном и полноэкранном режиме, нижние кнопки со всеми состояниями, попапы) **вставляются из плагина** и перекрашиваются той же темой;
4. **проблемы ловятся до хэндоффа**: непривязанные цвета, контраст;
5. разработчик в Dev Mode видит **имена CSS-переменных Telegram**.

### Метрики успеха (для себя)
- Проверка экрана в 5+ темах занимает меньше минуты вместо ~20 минут ручной работы.
- 100% цветов контента привязаны к theme params или явно помечены как исключение.
- Системная обвязка в макете — компоненты плагина со всеми состояниями, а не скриншоты.

---

## 3. Пользователи

- **Основной:** продуктовый дизайнер, который делает нативный Mini App.
- **Вторичный:** фронтенд-разработчик, который читает макет в Dev Mode.

## 4. Модель данных

### 4.1. Theme params
Актуальный набор ключей (по документации Telegram / TDLib, 15 штук). Все необязательные, значение — hex `#RRGGBB`.

| Ключ (`themeParams`) | CSS-переменная | Назначение |
|---|---|---|
| `bg_color` | `--tg-theme-bg-color` | Основной фон |
| `secondary_bg_color` | `--tg-theme-secondary-bg-color` | Вторичный фон |
| `header_bg_color` | `--tg-theme-header-bg-color` | Фон шапки |
| `bottom_bar_bg_color` | `--tg-theme-bottom-bar-bg-color` | Фон нижней панели |
| `section_bg_color` | `--tg-theme-section-bg-color` | Фон секций/карточек |
| `section_separator_color` | `--tg-theme-section-separator-color` | Разделители |
| `text_color` | `--tg-theme-text-color` | Основной текст |
| `accent_text_color` | `--tg-theme-accent-text-color` | Акцентный текст |
| `section_header_text_color` | `--tg-theme-section-header-text-color` | Заголовки секций |
| `subtitle_text_color` | `--tg-theme-subtitle-text-color` | Подзаголовки |
| `destructive_text_color` | `--tg-theme-destructive-text-color` | Деструктивные действия |
| `hint_color` | `--tg-theme-hint-color` | Подсказки, второстепенный текст |
| `link_color` | `--tg-theme-link-color` | Ссылки |
| `button_color` | `--tg-theme-button-color` | Фон кнопки |
| `button_text_color` | `--tg-theme-button-text-color` | Текст на кнопке |

> ⚠️ Перед разработкой сверить список с https://core.telegram.org/bots/webapps — Telegram периодически добавляет ключи. Держать список в одном конфиге.

### 4.2. Пресеты тем
Пресет — это `{ name, platform: 'ios'|'android'|'desktop', scheme: 'light'|'dark', params }`.

Минимальный набор для MVP:
1. iOS — светлая
2. iOS — тёмная
3. Android — светлая
4. Android — тёмная
5. Desktop — тёмная
6. «Злая» кастомная тема для стресс-теста
7. Пользовательский пресет — вставить JSON

Пример реального значения (тёмная тема, из документации telegram-mini-apps.com):
```json
{
  "accent_text_color": "#6ab2f2",
  "bg_color": "#17212b",
  "button_color": "#5288c1",
  "button_text_color": "#ffffff",
  "destructive_text_color": "#ec3942",
  "header_bg_color": "#17212b",
  "hint_color": "#708499",
  "link_color": "#6ab3f3",
  "secondary_bg_color": "#232e3c",
  "section_bg_color": "#17212b",
  "section_header_text_color": "#6ab3f3",
  "subtitle_text_color": "#708499"
}
```

> ⚠️ Точные значения остальных пресетов **не выдумывать**. Снять их с реальных клиентов: открыть тестовый Mini App в каждом клиенте, залогировать `JSON.stringify(Telegram.WebApp.themeParams)` и сохранить в `presets/*.json`. Для этого сделать маленькую страницу-«снифер».

### 4.3. Платформа пресета
Пресет знает свою платформу. При смене темы системные компоненты переключают не только цвета, но и **вариант платформы** (iOS / Android / Desktop), потому что шапка и кнопки на них выглядят по-разному.

## 5. Скоуп MVP

### Блок A. Система тем

#### A1. Коллекция переменных `Telegram Theme`
- Кнопка «Подключить Telegram Theme».
- Плагин создаёт коллекцию Figma Variables:
  - 15 COLOR-переменных с именами ключей (`tg/bg_color` и т.д.);
  - по одному **mode** на каждый пресет;
  - `codeSyntax.WEB` = `var(--tg-theme-bg-color)` и т.д., чтобы в Dev Mode была видна CSS-переменная.
- Повторный запуск обновляет значения и добавляет недостающее, ничего не удаляя.

#### A2. Переключение темы
- Выбираешь фрейм(ы) → выбираешь пресет → на фрейме выставляется явный mode коллекции.
- Всё, что привязано к переменным, перекрашивается мгновенно.
- Инстансы системных компонентов внутри фрейма переключаются на вариант платформы пресета (см. блок B).

#### A3. Матрица тем
- Выбираешь экран → отмечаешь пресеты → «Разложить по темам».
- Плагин дублирует фрейм, ставит копии в ряд, на каждую — свой mode и платформу, сверху подпись.
- Результат кладётся в секцию `TG Theme Preview — <имя экрана>`. Повторный запуск её пересоздаёт. Исходный экран не меняется.

### Блок B. Системные компоненты Telegram

Плагин вставляет в файл набор системных компонентов (на отдельную страницу `TG System Components`) и даёт вставлять их инстансы в экраны из UI плагина. **Все цвета компонентов привязаны к переменным `Telegram Theme`**, поэтому они перекрашиваются вместе с темой.

#### B1. Шапка Mini App — оконный режим (compact / fullsize)
Варианты:
- **Платформа:** iOS / Android / Desktop.
- **Левая кнопка:** Close / Back (Back показывается, когда приложение включило `BackButton`).
- **Правая кнопка:** меню «⋯» (в меню может быть пункт Settings, если приложение включило `SettingsButton`).
- **Заголовок:** имя бота / приложения, опционально подзаголовок.
- **Цвет шапки:** по умолчанию `header_bg_color`; вариант с `bg_color` / `secondary_bg_color` / произвольным цветом, как через `setHeaderColor`.
- **Режим высоты контейнера:** compact (половина экрана, видно чат под ним) / fullsize.
- **Состояния кнопок:** default / pressed.
- Иконки и текст в шапке подстраиваются по контрасту к цвету шапки.

#### B2. Шапка Mini App — полноэкранный режим (fullscreen)
- Нативной шапки нет, контент на весь экран. Поверх контента — **плавающие системные контролы** (Close/Back слева, «⋯» справа).
- Варианты: платформа, Close / Back, светлые / тёмные контролы (в зависимости от фона под ними), default / pressed.
- Отдельный компонент-**оверлей safe area**: системная safe area (статус-бар, вырез, home indicator) и content safe area (зона под системными контролами). Используется как гайд, на экспорт не идёт.

#### B3. Нижняя панель: MainButton и SecondaryButton
- **Раскладки bottom bar:**
  - только MainButton;
  - MainButton + SecondaryButton по горизонтали (Secondary слева или справа);
  - MainButton + SecondaryButton по вертикали (Secondary сверху или снизу);
  - только SecondaryButton.
- **Состояния каждой кнопки:**
  - default;
  - pressed;
  - inactive (`isActive = false`, приглушённая);
  - loading (`showProgress`, спиннер вместо текста);
  - shine effect (`has_shine_effect`, переливающийся блик);
  - hidden (для прототипов: панель без этой кнопки).
- **Цвета:** по умолчанию MainButton — `button_color` / `button_text_color`; SecondaryButton — по документации (сверить, у неё свой дефолт); фон панели — `bottom_bar_bg_color`. Вариант «кастомный цвет», как через `setParams`.
- **Платформа:** iOS / Android / Desktop (отличаются скругления, отступы, safe area снизу).

#### B4. Нативные попапы
- `showPopup` (заголовок, текст, 1–3 кнопки с типами default / ok / close / cancel / destructive), `showAlert`, `showConfirm`.
- Варианты по платформам, цвета — из темы.

#### B5. Фрейм-шаблон экрана
- «Новый экран Mini App»: создаёт фрейм нужной платформы с шапкой (оконный или fullscreen режим), областью контента с фоном `bg_color` и bottom bar. Это стартовая точка для любого экрана.

> ⚠️ Точный вид, размеры, иконки и поведение обвязки **снимать с актуальных клиентов** (скриншоты iOS, Android, Desktop в светлой и тёмной теме, все режимы). Названия методов и параметров сверить с https://core.telegram.org/bots/webapps: `BackButton`, `SettingsButton`, `MainButton`, `SecondaryButton`, `setHeaderColor`, `setBottomBarColor`, `requestFullscreen`, `safeAreaInset`, `contentSafeAreaInset`, `showPopup`. Часть из них доступна только с определённых версий Bot API.

### Блок C. Проверки

#### C1. Аудит непривязанных цветов
- Обход выделения: fills / strokes / текст с **сырыми цветами**, не привязанными к `Telegram Theme`.
- Для каждого — слой, цвет и предложение ближайшего theme param (по светлой теме iOS).
- Действия: **Привязать**, **Пометить как исключение** (иллюстрации, фото, брендовый логотип; в `pluginData`, больше не показывать), **Показать на холсте**.
- «Привязать все предложенные» — с подтверждением.

#### C2. Контраст по всем темам
- Для каждой текстовой ноды найти эффективный фон: ближайший родитель с непрозрачным fill.
- В каждом пресете посчитать контраст WCAG 2.1 с учётом значений переменных в этом mode.
- Таблица «слой × тема → коэффициент», подсветка < 4.5 (обычный текст) и < 3 (крупный).

### Блок D. Хэндофф
- Благодаря `codeSyntax` разработчик видит CSS-переменные в Dev Mode.
- Кнопка «Скопировать для разработки»: JS-сниппет по экрану — какие системные кнопки включить и в каком состоянии, цвет шапки и bottom bar, если он отличается от дефолта. Например:
  ```js
  const tg = window.Telegram.WebApp;
  tg.BackButton.show();
  tg.MainButton.setParams({ text: 'Продолжить', is_active: true, is_visible: true });
  tg.SecondaryButton.setParams({ text: 'Отмена', position: 'left', is_visible: true });
  ```

## 7. Технические опоры

- **Платформа:** Figma Plugin API, TypeScript. UI — iframe (`figma.showUI`), Preact/Svelte или ванильный TS; сборка — esbuild или Vite. UI ↔ main thread через `postMessage`.
- **Ключевые API** (сверить с https://www.figma.com/plugin-docs/):
  - переменные: `figma.variables.createVariableCollection`, `addMode`, `createVariable(..., 'COLOR')`, `setValueForMode`, `setVariableCodeSyntax('WEB', ...)`, `setBoundVariableForPaint`;
  - режимы: `node.setExplicitVariableModeForCollection`;
  - компоненты: `figma.createComponent`, `figma.combineAsVariants`, `addComponentProperty`, `instance.setProperties`;
  - данные: `setPluginData` / `getPluginData`;
  - `figma.createSection`, `figma.loadFontAsync`;
  - манифест с `documentAccess: "dynamic-page"` и асинхронными getter'ами.
- **Как поставлять системные компоненты** — выбрать один из вариантов:
  1. плагин **генерирует компоненты кодом** в файле пользователя (полный контроль, всё в плагине, но больше работы);
  2. плагин хранит компоненты как **сериализованный SVG/JSON** и собирает их в файле, потом привязывает цвета к переменным;
  3. компоненты лежат в **опубликованной библиотеке**, плагин импортирует их через `importComponentByKeyAsync` (проще поддерживать, но пользователю нужен доступ к библиотеке).
  Для MVP рекомендуется вариант 1 или 2: плагин самодостаточен.
- **Цвета:** парсинг hex, OKLab или ΔE (CIEDE2000) для подбора ближайшего theme param, относительная яркость WCAG 2.1 для контраста и выбора светлых или тёмных иконок.
- **Структура репо (предложение):**
  ```
  /src
    /main         # работа с документом Figma
    /ui           # интерфейс плагина
    /core         # чистые функции: цвета, контраст, матчинг, сниппеты — покрыть тестами
    /components   # описания системных компонентов по платформам (размеры, отступы, иконки, состояния)
  /presets        # JSON-пресеты тем
  /reference      # скриншоты клиентов, по которым сверяются компоненты
  manifest.json
  ```

## 8. Критерии приёмки MVP

**Темы**
- [ ] Создаётся коллекция `Telegram Theme` с 15 переменными и ≥ 6 modes; повторный запуск ничего не дублирует и не ломает.
- [ ] В Dev Mode у привязанного цвета видна CSS-переменная Telegram.
- [ ] Переключение темы на фрейме работает в один клик и переключает платформу системных компонентов.
- [ ] Матрица тем генерируется в отдельную секцию, исходный экран не меняется.

**Системные компоненты**
- [ ] Шапка в оконном режиме: iOS / Android / Desktop × Close / Back × с меню / без × compact / fullsize, состояния default / pressed.
- [ ] Fullscreen: плавающие контролы для всех платформ + оверлей safe area.
- [ ] MainButton и SecondaryButton: все раскладки и состояния default / pressed / inactive / loading / shine / hidden.
- [ ] Попапы `showPopup` / `showAlert` / `showConfirm` по платформам.
- [ ] Все цвета компонентов привязаны к `Telegram Theme` и корректно перекрашиваются во всех пресетах.
- [ ] Компоненты визуально сверены с референсами из `/reference`.

**Проверки и хэндофф**
- [ ] Аудит находит все непривязанные solid-цвета, предлагает переменную, умеет привязать и пометить как исключение.
- [ ] Контраст считается для всех пресетов, проблемные пары подсвечиваются.
- [ ] «Скопировать для разработки» выдаёт рабочий JS-сниппет.
- [ ] Модуль `/core` покрыт unit-тестами.

## 9. Риски и открытые вопросы

1. **Лимит modes в коллекции зависит от тарифа Figma.** На бесплатном плане их может не хватить. Проверить лимиты; фолбэк — несколько коллекций или перекраска копий без переменных.
2. **Точность системных компонентов.** Шапка, кнопки и попапы отличаются между версиями клиентов. Держать размеры и отступы в одном конфиге `/components`, референсы — в `/reference`, обновлять по мере выхода новых версий.
3. **Версии Bot API.** SecondaryButton, bottom bar, fullscreen, shine effect появились не сразу. Решить, помечать ли это в компонентах («доступно с Bot API X»).
4. **Актуальность пресетов.** Telegram меняет дефолтные палитры — снифер из п. 4.2 должен позволять быстро обновить JSON.
5. **Шрифты платформ.** SF Pro / Roboto могут быть недоступны в файле — нужен фолбэк и предупреждение.
6. **Градиенты и прозрачность.** В MVP аудит и контраст — только для solid-цветов; остальное в отчёт как «не поддерживается».
7. **Инстансы из внешних библиотек.** Привязка внутри инстанса — оверрайд. Решить, предлагать ли правку в мастер-компоненте.
8. **Бренд Telegram.** При публикации в Community не использовать логотипы и брендовые ассеты Telegram сверх необходимого для системного UI.

## 10. Порядок работы (предлагаемые шаги)

1. Снифер theme params, снять 5–6 реальных пресетов; собрать скриншоты обвязки в `/reference`.
2. Скелет плагина: манифест, сборка, пустой UI.
3. Модуль `/core`: цвета, контраст, матчинг, сниппеты + тесты.
4. Коллекция `Telegram Theme` (A1) и переключение темы (A2).
5. Шапка в оконном режиме для iOS (B1), затем Android и Desktop.
6. MainButton / SecondaryButton со всеми раскладками и состояниями (B3).
7. Fullscreen-контролы и safe area (B2).
8. Шаблон экрана (B5) и матрица тем (A3).
9. Попапы (B4).
10. Аудит цветов (C1) и контраст (C2).
11. Хэндофф-сниппет (D).
12. Обкатка на реальных макетах.
